## 一、集成总览

### 1.1 7 个子系统的集成背景

所有 7 个子系统（经济 #19、灵根 #20、战斗 #21、区域 #22、声望 #23、任务链 #24 + 清理 #18）已在各自独立工作中完成实现。各子系统均已在 02-扩充内容/ 目录下产出了完整的设计文档（含 LPC 数据接口），并且在 `.knowledge/RELATIONS.md` 中记录了子系统间的关联边。

P3 集成阶段的目标是：将 7 个子系统接通为可协作的统一游戏框架，并通过全局数值验证确认整体经济/成长/战斗平衡。

### 1.2 集成的核心挑战

```
┌──────────────────────────────────────────────────────┐
│                   P3 集成总览                          │
│                                                        │
│   经济系统 ←→ 灵根养成 （灵石消耗 + 灵根洗练开销）       │
│      ↑              ↑                                  │
│      ↓              ↓                                  │
│   战斗系统 ←→ 区域玩法 （战斗产出 + 秘境门票消耗）       │
│      ↑              ↑                                  │
│      ↓              ↓                                  │
│   声望系统 ←→ 任务系统 （声望解锁 + 任务奖励注入）       │
│                                                        │
│   ┌──────────────────────────────────────────────┐     │
│   │              全局数值验证                      │     │
│   │  收入模型 | 支出模型 | 成长曲线 | 战斗平衡     │     │
│   └──────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────┘
```

### 1.3 拆分策略

基于上述关联图谱，将 P3 集成拆分为两道独立工序：

| 子 ticket | 聚焦 | 依赖方向 |
|-----------|------|---------|
| **#25-A 经济循环基础设施** | 灵石产出/消耗对接各子系统、经济模型运行 | 所有子系统需提供收入/支出接口 |
| **#25-B 跨系统联动+全局平衡验证** | 跨系统联动链路测试、全局数值验收 | 依赖 #25-A 的经济循环就绪 |

## 二、子 ticket 拆分方案

### 2.1 #25-A：经济循环基础设施

#### 工作范围

将所有子系统的灵石收支接口接入经济模型，并打通如下循环链路：

**（A1）经济→修炼循环**
- 灵石灌注修炼（从玩家灵石扣减 → 转化为修为值/lpm）
- 聚灵阵消耗（灵石消耗 vs. 修炼速度增益的数值配对）
- 文档参考：02-经济与资源.md 第1-2章、02-灵根养成与突破.md 第3章

**（A2）经济→战斗循环**
- 阵法维持的灵石消耗（战斗中每回合扣减灵石维持阵法）
- 装备维修费用（耐久度消耗 → 灵石回收）
- PVP 死亡惩罚（败者损失携带灵石的 10-30%）
- 比武报名费
- 文档参考：02-经济与资源.md 第1.2章、02-战斗机制与平衡.md 第3章

**（A3）经济→区域循环**
- 传送阵费用（跨区域快速旅行的灵石消耗）
- 秘境门票（进入副本/秘境的灵石门槛）
- 洞府维护费（私人修炼空间的定期开销）
- 宗门驻地维护（帮会层级的灵石投入）
- 文档参考：02-经济与资源.md 第1.2章、02-区域游戏玩法.md 第4章

**（A4）经济→任务循环**
- 任务奖励的灵石注入（系统产出的主渠道）
- 任务失败惩罚（灵石/修为扣减）
- 每日活跃度与任务奖励的经济约束
- 文档参考：02-任务链与奖励曲线.md 第3章、02-经济与资源.md 第5章

**（A5）经济→声望循环**
- 势力任务奖励的灵石注入
- 声望等级解锁高级消费门槛
- 势力产业的税收（坊市/矿脉/拍卖行抽成）
- 文档参考：02-经济与资源.md 第4章、.knowledge/factions/1D-门派种族声望.md

**（A6）经济自身循环跑通**
- 动态定价模型（供需调整商品价格）
- 灵石产出总量控制（各境界产出系数）
- 灵石回收通道运作（税率/手续费/死亡惩罚）
- 全服通胀监控机制
- 文档参考：02-经济与资源.md 第1.3、6章

#### 验收标准

| 检查项 | 验收条件 |
|--------|---------|
| 经济→修炼接口 | 消耗灵石可兑换修为值，聚灵阵实际扣费与设计一致 |
| 经济→战斗接口 | 阵法维护/装备维修/PVP惩罚消耗正确扣减灵石 |
| 经济→区域接口 | 传送/秘境/洞府各消费通道的灵石流向正确 |
| 经济→任务接口 | 任务奖励灵石按奖励曲线模型注入，不超限 |
| 经济→声望接口 | 声望等级消费门槛有效，势力税收正常运作 |
| 经济自身循环 | 产出总量控制 ≤ 设计上限，回收通道扣减正确 |
| 全服通胀监控 | 通胀警戒/危险阈值触发对应的自动调整事件 |

### 2.2 #25-B：跨系统联动与全局平衡验证

#### 工作范围

在 #25-A 经济循环就绪的基础上，执行以下跨系统联动测试与全局平衡验证：

**（B1）灵根→战斗联动测试**
- 不同灵根品质对修炼速度的实际影响（T0-T4 对照）
- 灵根五行属性对法术伤害的修正（相克/相生倍率）
- 灵根洗练成本在经济模型中的合理性验证
- 文档参考：02-灵根养成与突破.md 第5章、02-战斗机制与平衡.md 第1.2章

**（B2）战斗→经济联动测试**
- 战斗产出（妖兽掉落/比武奖励）与消耗（维修/阵法/死亡）的比值是否符合设计目标（产出 > 消耗 15-25%）
- PVP/PVE 战斗在各境界的预期收益与实际对比
- 文档参考：02-战斗机制与平衡.md 第3、5章、02-经济与资源.md 第1.3章

**（B3）任务→境界成长联动测试**
- 主线任务链各阶段奖励是否与对应境界的修炼成本匹配
- 日常/周常任务提供的修炼资源是否足够支撑合理成长速度
- 任务链经验-时间比是否流畅（不卡点、不缺资源）
- 文档参考：02-任务链与奖励曲线.md 第3、4章、.knowledge/cultivation/CULTIVATION_SYSTEM.md

**（B4）区域→任务→声望联动测试**
- 区域解锁是否按任务链的章节推进（人界→乱星海→大晋→灵界）
- 声望门槛是否有效绑定任务解锁（如星宫声望≥友善才开启星宫链）
- 区域秘境门票价格在各境界的承受力验证
- 文档参考：02-区域游戏玩法.md 第5章、02-任务链与奖励曲线.md 第1.2章

**（B5）全局收支验证**
- 运行各境界（炼气→大乘）的预期日收支模型
- 检验全生命周期灵石累计是否为正（可玩性保障）
- 灵石产出/消耗比例是否维持在 1.15-1.25 区间
- 境界突破成本是否被各子系统合理分摊
- 文档参考：02-经济与资源.md 第5章

**（B6）境界成长曲线验证**
- 境界经验需求曲线 vs. 各子系统提供的修炼速度
- 从创建角色到大乘期的大致游戏时间估算
- 瓶颈概率与突破成本的经济压力验证
- 文档参考：.knowledge/cultivation/1C-修仙境界功法.md

**（B7）战斗平衡验证**
- 五行克制系统在跨境界战斗中的实际效果
- 技能连招收益与法力消耗的性价比
- PVE 怪物数值与同境界玩家的战力比值（建议 0.8-1.2）
- PVP 胜率分布是否平衡
- 文档参考：02-战斗机制与平衡.md 第3-5章

#### 验收标准

| 检查项 | 验收条件 |
|--------|---------|
| 灵根→战斗联动 | 灵根品质/五行属性正确影响战斗数值 |
| 战斗→经济联动 | 战斗产出/消耗比例 1.15-1.25 |
| 任务→成长联动 | 各境界任务奖励与修炼成本匹配不卡点 |
| 区域→任务→声望 | 区域解锁/声望门槛/任务触发链条正确 |
| 全局收支 | 全生命周期灵石为正，各境界不破产 |
| 境界成长曲线 | 修炼速度合理，从炼气到大乘时间可接受 |
| 战斗平衡 | PVE/PVP 数值平衡，五行克制系统有效 |
| 跨系统全链路 | 灵根→战斗→经济→任务→声望 全链路一次通过 |

```

                 └──────────┬───────────┘
                            │
                            ▼
                 ┌──────────────────────┐

                 │  (A1~A6 六条循环对接)   │
                 └──────────┬───────────┘
                            │
                            ▼
                 ┌──────────────────────────┐
                 │  #25-B: 跨系统联动+平衡验证 │
                 │  (B1~B7 七项测试)          │

                            │
                            ▼
                 ┌──────────────────────────┐
                 │  #25: 整体集成验收        │
                 │  全部通过 → close #25    │
```

- #25-A 和 #25-B 有**弱依赖**（B 依赖 A 的经济循环就绪），A 完成后 B 再启动
- 两个子 ticket 各派一名 worker 串行处理（A → B）
- 子 ticket 各自完成后，最终回到 #25 做整体收尾

## 四、风险与注意事项

| 风险 | 影响 | 缓解 |
|------|------|------|
| 某子系统实际实现与设计文档偏离 | 接口对接错位 | 开始集成前先对照设计文档做一次实现审计 |
| 全局收支不平衡（灵石产出 > 消耗太多） | 通胀失控 | A6 通胀监控机制必须优先实现，调整产出系数 |
| 境界成长曲线过慢或过快 | 玩家体验差 | B6 提供多组数列模拟，调整修炼倍率 |
| 跨境界战斗平衡失效 | 高阶碾压/低阶无体验 | B7 设置 PVE 强度梯度，允许组队抗压 |
