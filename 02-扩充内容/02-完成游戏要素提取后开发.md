## 三、详细实施分解

### 3.1 P0 基础层：经济体系代码实现（对应 #15 经济与资源）

#### 3.1.1 修改 moneyd.c —— 产出总控模块

**现状**：`adm/daemons/moneyd.c` 已有基础的灵石经济管理。需要补充：

- **产出总控函数**：`query_daily_output_limit(int realm_level)` → 返回某境界玩家的日产出上限
- **活跃度修正**：`get_activity_modifier(int online_minutes)` → 返回 0.3~1.1 的修正系数
- **全服阈值监测**：`check_server_supply()` → 计算人均持灵石量，触发自动调整

**文件**：`adm/daemons/moneyd.c`（修改）+ `include/money.h`（新增常量定义）

#### 3.1.2 新增 economy_d —— 动态定价模块

**新建** `adm/daemons/economyd.c`，实现：

- `query_base_price(string item_type)` — 基准价查询
- `calculate_market_price(string item_id, int supply, int demand)` — 动态定价公式
- `get_profit_margin(string item_id)` — 利润空间分析
- `query_economy_health()` — 7 项经济健康指标

**引用公式**（来自 #15 文档）：
```
市价 = 基准价 × (1 + 需求系数 − 供给系数) × 区域修正系数
需求系数 = Σ(在线玩家数×境界权重) / 全服总产出
```
- 价格浮动范围：±50%（硬性边界）
- 每 15 分钟 recalculation 一次

#### 3.1.3 新增 inflation_d —— 通胀控制模块

**新建** `adm/daemons/inflationd.c`：

- 动态税率（灵石交易税随通胀自动调整：基准 5%，最高 20%）
- 自动经济事件触发器（灵气潮汐/妖兽潮/古修洞府/坊市特卖）
- 灵石回收通道（修炼消耗/传送费/炼制手续费）

**阈值体系**：
| 人均持灵 | 触发动作 |
|:--------:|---------|
| < 300 | 无动作（正常） |
| 301-500 | 税率上调至 8% |
| 501-800 | 税率 12% + 触发经济事件 |
| > 800 | 税率 20% + 紧急回收事件 |

#### 3.1.4 新增 finance 函数

`feature/finance.c` 中补充：
- `player_spending_daily_stat()` — 玩家日支出统计
- `query_wealth_level(object player)` — 玩家财富评级（赤贫/温饱/富裕/豪绅）

#### 3.4.3 传送网络系统

**修改** `adm/daemons/mapd.c`：

- 传送阵注册：`register_teleport(string area_id, mixed position)`
- 传送执行：`teleport_player(object player, string target_area)`
- 传送费用：基于距离两级计费（人界 100-10000 灵石、灵界 1000-50000）
- 传送解锁条件：声望等级/境界门槛/任务完成

**网络拓扑**（六级架构）：
```
城镇传送阵(免费) → 区域传送阵(收费) → 跨域传送阵(高费)
  → 跨国传送(昂贵) → 跨海传送(高价+声望) → 跨界面传送(极稀有)
```

### 3.7 P3 集成层：跨系统整合与联调

#### 3.7.1 经济 × 战斗
- 法宝炼制消耗灵石/材料 → 经济系统扣除
- 战斗修复装备消耗 → 灵石流出
- 阵法启动需要消耗灵石

#### 3.7.2 经济 × 灵根
- 灵根洗练消耗天材地宝
- 突破丹药成本计入经济循环
- 灵根品质影响修炼效率，间接决定玩家日灵气消耗

#### 3.7.3 区域 × 经济 × 任务

```
玩家在区域内通过任务获得灵石/材料
  → 材料用于法宝/丹药炼制
    → 成品在坊市交易（带动经济循环）
      → 赚取灵石用于洞府经营/灵根洗练/传送
        → 回到区域
```

#### 3.7.4 声望 × 区域 × 任务
- 高声望解锁高级区域/传送门
- 区域专属任务链要求该区域声望达标
- 声望等级决定任务奖励倍率

#### 3.7.5 全局平衡验证

| 验证点 | 期望值 | 数据来源 |
|-------|:-----:|---------|
| 炼气→筑基周期 | ~1-3 月（游戏月） | 突破概率 + 日常产出 + 丹药辅助 |
| 灵石产出/消耗比 | 0.9~1.1（长期稳定） | 经济 daemon 统计数据 |
| 高境界低境界经济差距 | ≤50x | 境界产出系数逐步验证 |
| 副本产出占全服产出比 | ≤30% | 监测各产出通道占比 |
| 各境界活跃玩家占比 | 金字塔递减 | 活跃度统计 |

### 4.3 代码实现原则

1. **以修改现有文件为主**：已有 `combatd.c`、`moneyd.c`、`familyd.c`、`taskd.c` 等 daemon 文件是扩展点，尽量不改结构只加函数
2. **新增 daemon 尽量独立**：`reputation_d.c`、`secret_realm_d.c`、`economyd.c` 等新 daemon 应当独立可测试
3. **数值常量外置配置**：所有境界倍率、概率、费用等数值定义在 `include/*.h` 头文件中，便于平衡调整
4. **每个改动附证明性测试**：属性类改动（灵根生成概率/伤害公式/经济产出）必须提供红→绿测试
5. **跨系统引用用 daemon 查询**：避免直接引用其他系统的数据结构，通过 daemon 查询函数交互

### 4.4 风险与注意事项

| 风险 | 缓解措施 |
|------|---------|
| 已有代码可能定义了冲突的变量/函数 | 每个改动前先 grep 搜索同名标识符 |
| 五行克制改动影响现有怪物/NPC | 先做兼容性测试，确保旧怪物有默认五行属性 |
| 经济控制可能影响已有收支 | 先在开发环境运行经济模拟，验证关键比值 |
| 灵根新增属性字段需迁移 | 保存函数兼容旧数据格式 |
| 并行开发导致 daemon 接口冲突 | 先确定各 daemon 的公共 API 签名 |
